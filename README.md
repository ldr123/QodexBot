# QodexBot

QodexBot 将 QQ 机器人 C2C 单聊和群聊消息转发给本机 Codex CLI，并把 Codex 的回复、图片和桌面操作结果发送回 QQ。管理页面只监听本机地址，配置与会话记录保存在程序运行目录。

## 功能

- 通过 QQ 机器人开放平台接收和回复 C2C 单聊及群聊消息，支持正式环境与沙箱环境。
- 支持绑定多个 QQ 机器人；每个机器人使用独立的网关连接、Codex app-server 和默认工作目录。
- 每个机器人的普通消息统一排队交给 Codex；本地指令并发处理，查询、截图、停止和补充回答不必等待 Codex 任务完成。
- 按当前工作区读取本机 Codex 项目会话；私聊用户和群聊中的各成员分别保存当前工作区与会话选择。
- 在 QQ 中通过可配置指令查看状态、管理个人会话、重试或停止任务，以及直接发送桌面截图。
- 将 Codex 生成的图片或本机图片直接发回 QQ。
- 向 Codex 提供截图、键鼠操作和向 QQ 用户提问等 MCP 工具。
- 提供本机管理页面和可分页查询的会话记录。
- 支持 Windows x64 Native AOT；运行发布包无需另行安装 .NET 运行时。

## 下载与运行

从 [GitHub Releases](https://github.com/RRQM/QodexBot/releases/latest) 下载最新的 `qodexbot-win-x64-aot-版本号.zip`，解压后运行 `QodexBot.exe`。首次启动会自动打开管理页面，默认地址为 <http://127.0.0.1:17890/>。

程序会在 `QodexBot.exe` 所在目录创建 `settings.json` 和 `conversations.jsonl`。请将程序解压到当前 Windows 用户可写入的目录。

## 首次配置

1. 打开管理页面，点击“添加机器人”，再为选中的机器人点击“扫码绑定 QQ”，使用手机 QQ 扫描并确认。可以重复添加并分别绑定多个机器人。
2. 选择正式或沙箱环境，并按平台要求开通 C2C/群聊权限、启用 `C2C_MESSAGE_CREATE` 和 `GROUP_AT_MESSAGE_CREATE` 事件订阅。管理页面可分别启用私聊和群聊处理。若要让机器人接收未 @它的普通群消息，还需在 QQ 开放平台申请并开启全量群消息（`GROUP_MESSAGE_CREATE`）事件。
3. 扫码成功后，程序会在本机保存该机器人的 AppID 和 AppSecret，并自动连接机器人。管理页可以分别设置每个机器人的环境、消息订阅和 QQ 指令。修改管理端口后需要重启程序。

AppSecret 以明文保存在运行目录的 `settings.json` 中。管理页面不会读回已保存的密钥；修改其他设置时，AppSecret 留空即可保留现有值。请妥善保护程序目录和 Windows 用户账户。

管理服务默认只监听 `127.0.0.1`，不要将其代理或暴露到公网。

## 使用 Codex CLI

机器人和 Codex CLI 必须运行在同一台 Windows 电脑、同一个 Windows 用户环境下。该用户需要安装 Node.js，并通过 npm 全局安装、登录 Codex CLI：

```powershell
npm install -g @openai/codex
codex login
```

程序按当前用户的 npm 全局安装路径查找 `@openai/codex/bin/codex.js`，并通过 `node.exe` 启动 `codex app-server`。每个机器人收到 QQ 网关 READY 后会启动自己的 app-server，启动时不会额外创建空会话。默认工作目录位于 Windows 临时目录下的 `QodexBot\bots\<机器人 ID>`，可在 QQ 中切换到实际项目目录。项目会话直接读取当前 Windows 用户的 Codex 历史，包含 CLI、桌面端/编辑器和 app-server 创建的未归档会话，按目录筛选并按最近更新时间排列。选择已有会话会继续其原有上下文，新建和改名直接写入 Codex。不同 QQ 用户的当前选择互相独立，同一项目的历史列表来自同一份 Codex 数据。

同一机器人的所有普通消息按接收顺序排队执行，同一时间只运行一个 Codex 任务。帮助、状态、会话列表、最近记录、工作目录、截图和停止等本地指令独立响应。新建、切换、重命名会话及切换模型也不等待当前任务结束；运行中的任务继续使用启动时的会话和模型，尚未执行的消息在开始执行时读取当前选择。重试会加入 Codex 队列；更新 Codex CLI 会先提示等待，再排队执行，避免更新过程中打断任务。Codex 提问时，用户的补充回答直接交给正在等待的任务，不进入普通消息队列。

## QQ 指令

发送 `/` 查看可用指令。参数直接跟在命令后，例如 `/切换 2`、`/标题 新名称`、`/切换工作区 D:\OpenCode\项目名称`。在管理页面的“QQ 指令”区域可自定义触发命令，留空可禁用对应动作。

默认采用 QQ 官方指令的 `/` 前缀。读取旧配置时，仍使用原默认反斜杠命令的绑定会自动迁移，自定义和已禁用的绑定保留；如新命令已被其他动作占用，则保留该旧绑定。要在 QQ 输入 `/` 时展示指令面板，还需在 QQ 开放平台的“发布设置 → 功能配置 → 指令配置”中配置相应指令，并与本程序的触发命令保持一致。

- `/会话` 显示当前项目的 Codex 历史，`/会话 2` 查看第二页；每页 10 项，编号在所有页之间连续。使用 `/切换 编号` 选择，按最近展示的列表匹配会话 ID，避免排序变化导致选错。
- `/模型列表` 列出模型，也可附页码；使用 `/模型 名称或编号` 切换。
- `/切换工作区 绝对路径` 切换项目，路径含空格时可加引号。切换到另一项目时清除当前会话选择并展示该项目的 Codex 会话。新建会话使用当前项目目录；未选择会话时直接发送普通消息也会创建新会话。
- 缺少必要参数时只返回用法提示。单独发送数字、名称、路径或“菜单”均按普通消息处理，不作为后续菜单输入；Codex 等待补充回答时，普通消息直接交给该任务。
- 正在运行的任务继续使用原目录和会话，后续排队任务使用执行时选定的项目与会话。本地指令可在任务运行时独立响应。

默认绑定如下：

| 默认命令 | 动作 |
| --- | --- |
| `/` | 显示指令列表 |
| `/状态` | 查看机器人和 Codex 状态 |
| `/会话 [页码]` | 列出当前工作区的 Codex 项目会话 |
| `/切换 编号` | 按列表编号切换会话 |
| `/新建 [名称]` | 创建并切换到新会话 |
| `/最近` | 查看最近的对话摘要 |
| `/当前` | 查看当前会话名称 |
| `/标题 新名称` | 重命名当前会话 |
| `/工作目录` | 查看 Codex 工作目录 |
| `/切换工作区 绝对路径` | 切换项目并展示其 Codex 会话 |
| `/截图` | 直接截取桌面并发送到 QQ |
| `/重试` | 重发最近一次请求 |
| `/停止` | 中断当前 Codex 任务 |
| `/模型列表 [页码]` | 列出可用模型 |
| `/模型 名称或编号` | 切换模型，不带参数时显示当前选择和用法 |
| `/额度` | 查看当前 Codex 登录账号的额度使用情况和重置时间 |
| `/更新Codex` | 更新全局 Codex CLI 并重启 app-server |

指令在机器人端直接处理，必要时查询或修改 Codex 会话元数据；普通消息才会启动 Codex 任务。当前工作区、选中会话 ID 和模型偏好保存在程序目录的 `conversation-state.json`，按机器人、私聊用户或“群 + 群成员”区分。不再维护或读取 `sessions.json` 会话清单；会话标题、历史和项目归属均以 Codex 为准。群聊回复会引用触发消息，防止同一消息因同时推送 @事件和全量事件而重复处理。更新指令使用 npm 全局安装最新版 `@openai/codex`，并自动重启当前机器人的 app-server。

## QQ 和桌面 MCP 工具

程序通过本机随机命名管道连接 MCP 服务，不开放公网 MCP 端口。Codex 会话可以调用以下工具：

| 工具 | 用途 |
| --- | --- |
| `qq_capture_screen(processName?)` | 不传进程名时截取整个桌面；指定进程名（如 `Code`、`notepad`）时截取该进程面积最大的可见窗口，并发送到当前 QQ 对话。 |
| `qq_send_image(path)` | 发送 `QodexBot\qq-outbox` 目录中的 PNG/JPEG 图片到当前 QQ 对话。 |
| `qq_ask_user(question)` | 向当前 QQ 对话提问，并等待该用户的下一条消息作为回答；等待时间为 5 分钟。 |
| `qq_input(action, ...)` | 对当前焦点窗口执行键盘输入或鼠标操作。支持 `type_text`、`press_key`、`click`、`move_mouse` 和 `scroll`。 |

截图和上传图片均受 QQ 的 10 MiB 图片限制。`qq_input` 使用虚拟屏幕绝对坐标；桌面截图和输入需要 Windows 交互桌面处于已登录、未锁屏状态。Windows 锁屏时会切换到受保护的桌面，普通程序无法读取该画面；在虚拟机中需要锁屏截图时，请改用宿主机或虚拟化平台提供的控制台截图。程序按每台显示器的 DPI 感知虚拟屏幕尺寸进行桌面截图和坐标处理。程序同一时间只执行一个 Codex 任务，并为最终答复预留 QQ 消息回复额度。本地截图指令使用独立的回复上下文，不会覆盖正在运行的 Codex 任务。

Codex 对话回复和补充问题使用 QQ Markdown 消息发送，需要机器人已获批被动 Markdown 能力；AI 回复遵循 QQ 支持的 Markdown 子集，图片仍以独立富媒体消息发送。

## 从源码运行和发布

开发环境需要 .NET 10 SDK、Node.js 和已登录的 Codex CLI。在仓库根目录运行：

```powershell
dotnet run --project src/QodexBot/QodexBot.csproj
```

QQ 扫码绑定由程序内的 C# 实现，不再需要额外安装 Node.js 扫码组件；Node.js 仍用于运行 Codex CLI。

运行测试：

```powershell
dotnet test src/QodexBot.slnx
```

截图测试会实际捕获 Windows 桌面，需要在已登录且未锁屏的交互桌面会话中运行。

版本号定义在 `src/Directory.Build.props`。将版本号更新后推送到 `main`，GitHub Actions 会比较推送前后的版本；版本有变化时，或该版本尚无 Release 时，自动发布 Windows x64 Native AOT 包并创建 GitHub Release。发布脚本也可在 Windows 上手动运行：

```powershell
./Publish-Packages.ps1 -NoPause
```

产物为 `artifacts/packages/qodexbot-win-x64-aot-版本号.zip`。

## 会话记录与日志

`conversations.jsonl` 会追加保存 QQ 用户消息、Codex 回复、推理摘要、提问与回答，以及图片发送事件；图片内容本身不会写入历史文件。群聊记录按群和成员 OpenID 组合标识。管理页面支持按 OpenID 筛选并分页查看记录。控制台会输出 QQ 消息、Codex 回复摘要和工具调用进度，请按敏感数据处理日志与会话文件。

## 常见问题

- **机器人 READY 但收不到消息：** 检查管理页的私聊/群聊开关、QQ 开放平台的对应权限和事件订阅（群 @消息需 `GROUP_AT_MESSAGE_CREATE`；普通群消息还需开启全量群消息 `GROUP_MESSAGE_CREATE`）、机器人使用范围，以及 IP 白名单。
- **找不到 Codex CLI：** 确认当前 Windows 用户已安装并登录 Codex CLI，且 `node.exe` 可从 PATH 启动。
- **桌面工具无法工作：** 确认程序处于已登录、未锁屏的 Windows 交互桌面会话。
- **图片发送失败：** 确认文件是 PNG/JPEG，位于 `qq-outbox` 目录且不超过 10 MiB；平台权限和单条消息回复次数也会影响发送。

更多 QQ 平台说明见[腾讯 QQ 机器人文档](https://github.com/tencent-connect/bot-docs)。
